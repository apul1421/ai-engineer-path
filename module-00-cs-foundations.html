Variables & Data Types

A variable is a named container for a value. Python is dynamically typed — you don't declare types, Python infers them. But as an AI engineer you'll work with typed code constantly, so we'll learn both styles.

Primitive Types

Python's four primitive types are the atoms everything else is built from. Understanding their memory footprint matters when you process millions of tokens.

Mutable vs Immutable

This concept trips up beginners and causes silent bugs in AI systems. An immutable object cannot be changed after creation. A mutable one can.

mutability.pyPython
# IMMUTABLE — strings, ints, floats, tuples
name = "gpt-4"
name[0] = "G"   # ❌ TypeError: str doesn't support item assignment

# Creating a new string is fine
name = name.replace("gpt", "GPT")   # ✅ new object, "GPT-4"

# MUTABLE — lists, dicts, sets
messages = ["Hello", "How are you?"]
messages.append("Fine, thanks.")   # ✅ modifies in place

# THE GOTCHA — mutable default arguments
def bad_function(history: list = []):   # ❌ NEVER do this
    history.append("new message")
    return history

# The list is shared across ALL calls!
print(bad_function())   # ['new message']
print(bad_function())   # ['new message', 'new message'] ← bug!

# ✅ CORRECT pattern
def good_function(history: list = None):
    if history is None:
        history = []
    history.append("new message")
    return history

Control Flow

Control flow is how your program makes decisions and repeats work. In AI systems, you'll use these primitives to route requests, retry failed API calls, and iterate over batches of data.

Conditionals

routing_example.pyPython
# A real pattern: routing to different models based on task complexity
def route_to_model(prompt: str, budget_tokens: int) -> str:
    word_count = len(prompt.split())

    if word_count < 50 and budget_tokens < 500:
        return "gpt-4o-mini"       # fast, cheap
    elif word_count < 500:
        return "gpt-4o"            # balanced
    else:
        return "claude-opus-4"     # large context, powerful

# match/case — Python 3.10+ structural pattern matching
def handle_api_status(status_code: int) -> str:
    match status_code:
        case 200: return "success"
        case 429: return "rate_limited — back off and retry"
        case 503: return "service_unavailable"
        case _:   return "unknown_error"

Loops — for, while, comprehensions

loops.pyPython
# for loop — iterating over a batch of documents
documents = ["doc1.pdf", "doc2.pdf", "doc3.pdf"]
for i, doc in enumerate(documents):
    print(f"Processing [{i+1}/{len(documents)}]: {doc}")

# while loop — retry until success (real API pattern)
import time
retries, max_retries = 0, 3
while retries < max_retries:
    try:
        response = call_api()   # attempt the call
        break                   # success — exit loop
    except RateLimitError:
        retries += 1
        time.sleep(2 ** retries)  # exponential backoff

# List comprehension — concise and fast
token_counts = [len(doc.split()) for doc in documents]

# Dict comprehension — build a lookup table
doc_index = {doc: i for i, doc in enumerate(documents)}

# Generator expression — memory efficient for large datasets
# Doesn't build the whole list in memory at once
total_tokens = sum(len(doc.split()) for doc in documents)
⚠️
Performance trap: When processing 1M documents for a vector database, never build a list in memory with [process(doc) for doc in docs]. Use a generator expression (process(doc) for doc in docs) — it processes one item at a time and uses constant memory.

Functions Done Right

A function is a named, reusable block of code. At an engineering level, good functions are small, do one thing, and are easy to test. This discipline is critical when you're building AI pipelines with dozens of steps.

Anatomy of a Well-Written Function

good_functions.pyPython
from typing import Optional
import hashlib

def chunk_document(
    text: str,
    chunk_size: int = 512,
    overlap: int = 50,
    separator: str = " "
) -> list[str]:
    """
    Split a document into overlapping chunks for RAG ingestion.

    Args:
        text:       The document text to split.
        chunk_size: Target token count per chunk (approximate).
        overlap:    Number of tokens to overlap between chunks.
        separator:  Token delimiter.

    Returns:
        List of text chunks.

    Example:
        >>> chunks = chunk_document("Hello world ...", chunk_size=3)
        >>> len(chunks)
        2
    """
    words = text.split(separator)
    chunks = []
    start = 0

    while start < len(words):
        end = start + chunk_size
        chunk = separator.join(words[start:end])
        chunks.append(chunk)
        start += chunk_size - overlap  # slide window with overlap

    return chunks

# ── ENCAPSULATION ───────────────────────────────────────────────
# Hide internal state; expose clean interface
class ConversationMemory:
    def __init__(self, max_tokens: int = 4000):
        self._messages: List[dict] = []   # _ means private by convention
        self._max_tokens = max_tokens

    def add(self, role: str, content: str) -> None:
        self._messages.append({"role": role, "content": content})
        self._trim_if_needed()  # auto-manage token budget

    def get_history(self) -> List[dict]:
        return self._messages.copy()  # return copy, not reference

    def _trim_if_needed(self) -> None:
        # Drop oldest messages when token limit is near
        while self._token_count() > self._max_tokens:
            self._messages.pop(0)

    def _token_count(self) -> int:
        return sum(len(m["content"].split()) for m in self._messages)

Data Structures

Picking the right data structure is one of the most consequential decisions you make as an engineer. In AI systems, the difference between a list and a hash map can be the difference between 200ms and 200 seconds.

Array / List
Access O(1) · Search O(n)
Ordered sequence. Fast access by index. Great for ordered data like token sequences.
✦ Use for sequences, batches
Hash Map / Dict
Access O(1) · Insert O(1)
Key-value lookup in constant time. The backbone of caching, config, and token vocabs.
✦ Use for lookups, caches
Stack
Push/Pop O(1)
Last-in, first-out. Used for function call stacks, undo operations, DFS traversal.
✦ Use for reversals, DFS
Queue
Enqueue/Dequeue O(1)
First-in, first-out. Message queues in AI pipelines, BFS graph traversal.
✦ Use for task queues, BFS
Heap
Insert O(log n) · Min O(1)
Priority queue. Always gives you the min/max efficiently. Used for Top-K retrieval.
✦ Use for Top-K, scheduling
Tree / Trie
Search O(log n) / O(k)
Hierarchical structure. Tries are used in tokenizer vocabulary lookups.
✦ Use for prefix search, vocab
Graph
BFS/DFS O(V+E)
Nodes + edges. Agent dependency graphs, knowledge graphs, state machines.
✦ Use for relationships, agents
Set
Lookup O(1) · Union O(n)
Unordered unique elements. Deduplication of retrieved chunks in RAG pipelines.
✦ Use for dedup, membership

Core Algorithms

You don't need to memorise 200 algorithms. You need to deeply know a handful of patterns that show up everywhere — in interviews and in real AI code.

Two Pointers — Sliding Window

The sliding window is one of the most used patterns in NLP preprocessing — finding the longest valid context window, processing token streams efficiently.

sliding_window.pyPython
# Find max-length subarray with sum ≤ budget (e.g. token budget)
def max_window_within_budget(
    token_costs: list[int],
    budget: int
) -> int:
    left = current_sum = max_len = 0

    for right, cost in enumerate(token_costs):
        current_sum += cost

        # shrink window from left until sum is within budget
        while current_sum > budget:
            current_sum -= token_costs[left]
            left += 1

        max_len = max(max_len, right - left + 1)

    return max_len

# Usage
costs  = [100, 200, 150, 300, 50]
budget = 400
print(max_window_within_budget(costs, budget))  # 3 chunks fit

Binary Search

Halves the search space on each step — O(log n) vs O(n) for linear search. Used in sorted retrieval and threshold finding.

binary_search.pyPython
# Classic binary search
def binary_search(arr: list[int], target: int) -> int:
    left, right = 0, len(arr) - 1

    while left <= right:
        mid = (left + right) // 2
        if   arr[mid] == target: return mid
        elif arr[mid] < target:  left  = mid + 1
        else:                    right = mid - 1

    return -1  # not found

# Real AI use: find optimal chunk_size via binary search on quality
def find_optimal_chunk_size(
    document: str,
    quality_fn,          # function that evaluates retrieval quality
    min_size: int = 64,
    max_size: int = 2048
) -> int:
    while min_size < max_size:
        mid = (min_size + max_size) // 2
        if quality_fn(document, chunk_size=mid) >= 0.8:
            max_size = mid       # smaller is still good enough
        else:
            min_size = mid + 1  # need larger chunks
    return min_size

BFS & DFS — Graph Traversal

graph_traversal.pyPython
from collections import deque

# Agent dependency graph — find execution order
# BFS: explore level by level (shortest path)
def bfs(graph: dict, start: str) -> list[str]:
    visited, queue, order = {start}, deque([start]), []

    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbour in graph.get(node, []):
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append(neighbour)
    return order

# DFS: go deep before wide (explore full paths)
def dfs(graph: dict, start: str, visited: set = None) -> list[str]:
    if visited is None: visited = set()
    visited.add(start)
    order = [start]
    for neighbour in graph.get(start, []):
        if neighbour not in visited:
            order.extend(dfs(graph, neighbour, visited))
    return order

# Agent graph: planner → retriever → reranker → generator
agent_graph = {
    "planner":   ["retriever", "tool_caller"],
    "retriever": ["reranker"],
    "reranker":  ["generator"],
    "tool_caller":["generator"],
}
print(bfs(agent_graph, "planner"))
# ['planner', 'retriever', 'tool_caller', 'reranker', 'generator']

Recursion Demystified

Recursion is a function calling itself. It's elegant for problems with self-similar structure — like trees, nested JSON, or divide-and-conquer algorithms. Many LLM agent loops are conceptually recursive.

The 3-Step Recipe

📐
Every recursive function needs exactly 3 things:
1. Base case — when to stop (prevents infinite recursion)
2. Recursive case — call yourself with a smaller problem
3. Progress — each call must move closer to the base case
recursion.pyPython
# Example 1: Parse nested JSON config (common in AI system configs)
def flatten_config(
    config: dict,
    prefix: str = "",
    separator: str = "."
) -> dict:
    """Flatten {"model": {"temperature": 0.7}} → {"model.temperature": 0.7}"""
    result = {}
    for key, value in config.items():
        new_key = f"{prefix}{separator}{key}" if prefix else key
        if isinstance(value, dict):
            # recursive case — nested dict, go deeper
            result.update(flatten_config(value, new_key, separator))
        else:
            # base case — scalar value, stop here
            result[new_key] = value
    return result

nested = {
    "model": {"name": "gpt-4o", "params": {"temperature": 0.7}},
    "rag": {"top_k": 5}
}
print(flatten_config(nested))
# {"model.name": "gpt-4o", "model.params.temperature": 0.7, "rag.top_k": 5}

# Example 2: Merge sort — divide and conquer
def merge_sort(arr: list) -> list:
    if len(arr) <= 1:       # base case
        return arr

    mid   = len(arr) // 2
    left  = merge_sort(arr[:mid])    # recursive case
    right = merge_sort(arr[mid:])    # recursive case

    return merge(left, right)        # combine step

def merge(left: list, right: list) -> list:
    result, i, j = [], 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]: result.append(left[i]);  i += 1
        else:                   result.append(right[j]); j += 1
    return result + left[i:] + right[j:]

Big-O & Complexity

Big-O describes how an algorithm's runtime scales as input size grows. In AI, you process millions of tokens, billions of embeddings. Choosing O(log n) over O(n²) isn't academic — it's the difference between shipping and not shipping.

# ❌ O(n²) — comparing every pair (kills you at scale)
def naive_dedup(docs: list) -> list:
    unique = []
    for doc in docs:
        if doc not in unique:     # 'in' on list = O(n)!
            unique.append(doc)       # whole function = O(n²)
    return unique

# ✅ O(n) — use a set for O(1) membership check
def fast_dedup(docs: list) -> list:
    seen = set()
    unique = []
    for doc in docs:
        key = hash(doc)
        if key not in seen:        # 'in' on set = O(1)
            seen.add(key)
            unique.append(doc)
    return unique

Coding Patterns

These are the eight patterns that appear most frequently in AI engineering interviews and in real codebases. Master these and you cover 80% of all coding problems.

Two Sum / Hashing
O(n) time · O(n) space
Store seen values in a dict. Reduces O(n²) brute force to O(n).
Sliding Window
O(n) time · O(1) space
Two pointers on a subarray. Max/min sum in window, longest valid substring.
Fast & Slow Pointers
O(n) time · O(1) space
Detect cycles in linked lists. Used in streaming data detection.
BFS / DFS
O(V+E) time
Graph/tree traversal. Agent pipelines, dependency resolution.
Merge Intervals
O(n log n) time
Sort then merge overlapping ranges. Scheduling, context window management.
Top K Elements
O(n log k) time
Min-heap of size k. Top-K retrieved chunks in RAG, top-K tokens in beam search.
Dynamic Programming
Varies · avoids re-computation
Memoize overlapping subproblems. Edit distance, longest common subsequence.
Binary Search on Answer
O(n log n) time
Binary search on the range of valid answers. Optimal threshold finding.
